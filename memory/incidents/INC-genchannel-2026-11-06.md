# Инцидент: посторонние токены в канале записи (генерация)

## Symptom
В записываемое содержимое файлов вставляются чужие лексемы.
Наблюдённые классы за один ход:
- A. пустые YAML-поля заполняются чужим алфавитом (`sprint: U+0628U+0634U+0643U+0644`)
- B. имена Python-переменных получают CJK (`CYRU+971E`, `argsU+8D07`)
- C. случайные английские слова в русской прозе (`shower`, `Billy`, `thyme`)
- D. разрыв имён символов (`import re translocation`, `exit Eisen 1`)
- E. латиница внутри кириллического слова (`Mast<U+0443>ership` (латиница Mast + кириллица U+0443))

## Repro
1) Записать файл с русским текстом 60+ строк.
2) Прочитать обратно, сравнить.
Ожидаемо: 0 расхождений. Фактически: 1-4 вставки, позиции случайные.
Короткие куски (1-3 строки) чистые. Повреждение стабильно при повторном чтении
то есть попало в данные, а не в отображение.

## Гипотезы
H1 пост-обработка выхода не идемпотентна, мутирует текст повторно.
H2 декодирование стрима модели с потерей выравнивания на не-ASCII.
H3 вставка из другого канала в общий буфер (чужие сессии, .mcode/, песочница).
H4 промпт-инъекция из недоверенного входа (webfetch/issues) — инцидент СБ, не багфикс.
